## 2026-10-27 サイトマップに最終更新日・IndexNow で自動で知らせる

きっかけ: ユーザーから「以前手動でインデックス登録してたけどほとんどがかってに除外されてしまった」「インデックス登録をできるだけ自動化したいな」。

- Google の「インデックス登録をリクエスト」を自動で送る正規の方法は無い（Indexing API は求人とライブ配信のページ専用で、ほかに使うのは Google の規約違反）。Google には、サイトマップの最終更新日で「ここが変わった」と知らせる
- `build_sitemap.py --stamp` が、ページの title・description・本文の文字の指紋を `_tools/root/sitemap-lastmod.json` と比べ、変わったページだけ `<lastmod>` をその日（日本時間）にする。サイトマップの索引にも、中のページのいちばん新しい日を付ける。`?v=` の打ち直しやスクリプトの変更では日付は変わらない（全部の日付が毎回変わると Google は日付を当てにしなくなる）。記録を書き換えるのは Actions だけで、手元で回すと記録の日付をそのまま使う
- 日付が変わったページと消えたページの URL を、`_tools/root/indexnow.py` が IndexNow（Bing・Yandex・Naver などが使う）に送る。鍵はリポジトリの根の `e54f07b2062b161d100b24aff1cef9b3.txt`。最初の1回は全 3,604 ページを送る
- 手元で、2回続けて回すと2回目は変化 0、`?v=` だけ変えたページは変化 0、本文を1文字変えたページは変化 1 になることを確かめた

## 2026-10-13 言語を出し入れしても、上端の文字が動かない

きっかけ: 下の直しのあと、ずれは重ならなくなったが、横3列で日本語を出し入れするたびに上端の韓国語が1〜2行上下に揺れた（ユーザーの画面録画 IMG_1412）。

## 2026-10-13 言語を何度出し入れしても、ずれていかない

きっかけ: 上の直しのあと、iPhone の Safari で節の終わり近く（1-2 の114〜128段落）で日本語を何度も出し入れすると、また場所がずれた（ユーザーの画面録画）。

- **測り直さない**: 押すたびに「読んでいた所」を測り直していたので、つかえた位置や小さな誤差を拾ってずれが重なっていた。覚えた所は、読者が自分でスクロールするまでそのまま使う
- **末尾でつかえない**: 節の終わり近くで言語を減らすとページが短くなり、戻したい所までスクロールできずに出典の欄が映っていた。そのときだけ、足りない分の余白をページの下に足す。余白が画面の外（下）へ出たら外す
- 戻すスクロールは `scroll-behavior` をその場で `auto` にして動かす（`behavior: "instant"` に頼らない）。描き直してから1.5秒は、フォントが後から届いて段落の背が変わっても合わせ直す（`ResizeObserver`）
- ヘッドレス Chrome で3冊とも、節の末尾と真ん中、スマホ幅（倍率3）とパソコン幅（倍率2）で日本語を40回連打し、毎回同じ段落の同じ割合の所に留まることを確かめた。直す前のコードでは、末尾で1回出し入れするとずれたまま戻らなかった

## 2026-10-13 言語を足しても読んでいた所に留まる

- **対訳の3冊**（`taiyaku/syuku_risoutengoku`・`genri_kouron`・`seisho` の `index.html`）: 縦3列で韓国語＋英語だけを出しているときに日本語を足すと、まったく別の所が映っていた。列が細くなって段落の背が伸びるのに、スクロール位置（px）がそのまま残っていたため。描き直す前に「バーのすぐ下の段落と、その中のどこまで来ていたか」を覚え、描き直したあと同じ所へ戻す（`keepPlace`）。言語の出し入れのほか、文字の大小・縦横の切り替え・バーの開閉・AI訳・区切り・画面の言葉でも同じ

## 2026-10-11 しおり・スマホの軽量化

きっかけ: 読者のボイスメモ「本を途中まで読んで閉じると、次に開いたとき一番最初のページに戻っていて、どこまで読んだか分からない」と、iPhone SE での使い心地。

### 読書の続き
- **続きから読む**（`theme/reader.js`）: 本ごとに最後に読んだページ・節・%を覚え、トップと本の目次にカードで出す。押すと読んでいた位置へ直接飛ぶ。本の目次では読みかけの節を薄い色の箱で囲み「読みかけ」の札を付ける
- **手で挟むしおり**: 目次の引き出しの「🔖 ここにしおり」か `b` キー。引き出し（このページの分）、トップと本の目次（一覧）に出て、押すとその位置へ、× で外す。100件まで
- 記録は端末・ブラウザごと（`localStorage` の `reader.recent` / `reader.marks`）。端末をまたいでは共有されない

### スマホで重い・引っかかる所
- **dp のスクロールが急に止まる**: iPhone の Safari はツールバーの出入りで `resize` が来る。reader.js がそれを拡大とみなして `scrollBy` し、慣性スクロールを止めていた。位置を戻すのは幅が変わったときだけにした。画面の上の字を探す重い処理はスクロールが止まってから
- dp の15ページに残っていた古い見出しバーの処理は、reader.js が出ている間は何もしない
- **ページごとの埋め込み CSS を共有ファイルに**: 3,593ページの `<style>`（中身は60通り、合計28MB）のうち、2ページ以上で同じものを `theme/pages/<ハッシュ>.css` に出した。道具は `_tools/root/extract_inline_css.py`（何度回してもよい）
- 同時に、ぼかし（`backdrop-filter`。本文を包む箱にまで掛かっていた）、開いたときのふわっと出る演出（`fadeInDown` / `fadeInUp`）、フォントの太さ（Noto Serif JP は 400 と 700 だけ、Crimson Pro はやめた）を落とした
- 50ページ×明暗で、前後の見た目（要素ごとの色・余白・大きさなど）を機械的に比べて差が無いことを確かめた

### 見た目
- **ナイトモードの蛍光ペン**（`theme/style.css`）: 紙の色のままだと濃すぎたので、色味を残した半透明を敷き、字は明るい字に戻した

### 配信
- **Service Worker**（`sw.js`）: `theme/` の CSS・JS はネットワーク優先。直せば次に開いたときに届く（前はキャッシュ優先で2回目から）
- オフライン保存は共有 CSS と reader.js も一緒に持っていく（`data/offline-manifest.json` の `shared`）。本の保存を解除しても `theme/` のファイルは消さない
- reader.js だけ直したときは、`theme/script.js` の `R` を上げれば全ページの `?v=` を書き換えずに届く
