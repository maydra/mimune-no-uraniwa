# 韓英の対応付けと注（天一国経典『平和経』）

韓日の対応付け（TASK-align.md）が済んだので、同じことを韓国語と英語でやる。韓国語の原文と英語版を、講演ごとに
「どの韓国語のかたまりが、どの英語の文にあたるか」で対応させ、読む人向けの注も同じときに書く。**韓国語が正。**
目標は**韓国語も英語も1つ残らず、正しい相手と組になること**（ユーザーの方針: 入れ替えや補助の訳を入れてでも、正確に分けて組にする）。
英語があるのは73講演だけ（韓日英の連載に載っていた講演）。

## 材料（読むだけ。書き換えない）
- `work/sections-en/HHNN.txt` … 講演ごとの一覧。`K1:` が韓国語のかたまり（`[頭]` は日付・場所・行事の行、`[見出し]` は小見出し）、`E1 [p1]:` が英語の文（`[p1]` は英語版の段落、`[p4 見出し]` は小見出し）
- `work/sections/HHNN.json` … 同じ講演の JSON（`"ko"` と `"en"`。`{"ko"}` の字を機械で切り出すときに使う）
- 手本: 韓日の対応表 `work/align/HHNN.json`（形は同じで、`ja` が `en` になる。組の切り方や、韓国語の段落がどこまでかの参考になる）
- 英語版について分かっていること:
  - **日付・場所・行事の行が無い**（どの講演も）。講演の頭のあいさつなど、最初の小見出しより前の段落も無いことが多い
  - 日本語版より自由に訳していて、2〜3文を1文にまとめる、段落を組み替える、英語圏の読者向けに説明を足す、などがある

## 書くもの: `work/align-en/HHNN.json`

```json
{"key": "0101", "groups": [
  {"ko": [1], "en": [{"ko": "날 짜 : 1972년 2월 4일"}]},
  {"ko": [4], "en": [{"ko": "（K4 の全文）"}], "note": "英語版は頭のあいさつが無い"},
  {"ko": [5], "en": [1]},
  {"ko": [6], "en": [2, 3, 4]},
  {"ko": [7, 8], "en": [5, 6, 7], "note": "E6 が K7 の終わりと K8 の頭にまたがる"},
  {"ko": [9], "en": [8, {"ko": "그때 …"}, 9], "diff": ["In the original, …"]},
  {"ko": [10], "en": [10, 11], "en_only": [11], "en_only_ko": "…"}
]}
```

### 組の決まり（TASK-align.md と同じ）
- `groups` は韓国語の順に並べる。どの組も `ko`（韓国語の番号、連続した昇順）と `en`（英語）を持つ
- **組はできるだけ小さく。** ふつうは韓国語1かたまり＝1組。英語の1つの文が2つの韓国語のかたまりにまたがるときだけ、その韓国語をまとめて1組にする
- **`[頭]` と `[見出し]` の韓国語は、1つで1組にする**。英語の小見出しは、韓国語の小見出しの組に入れる
- `en` には、その韓国語にあたる英語の文の番号を、**韓国語の流れに沿う順**で並べる。英語版が順番を入れ替えている所は、韓国語の順に並べ直してよい
- **英語に無い韓国語**は、`en` の中のあるべき位置に `{"ko": "省かれている韓国語"}` として入れる。日付・場所・行事の行と、頭のあいさつの段落も、英語に無ければこの形で入れる。あとでここを英語に AI 訳して埋める
  - **字は原文からそのまま写す**（スクリプトが原文の中にあるかを確かめる）。`work/sections/HHNN.json` から機械で切り出すとよい。使い捨てのスクリプトはリポジトリの中ではなく scratchpad（`C:\Users\PC_User\AppData\Local\Temp\claude\E--auto-videos-creation\57799137-dc40-4ef5-8c7c-7a762b6632f5\scratchpad\`）に置き、**ファイル名に講演の番号を入れる**（`align_en_0305.py` など。ほかの担当も同時に使う）
  - 文、または読点で区切れる節がまるごと落ちていれば `{"ko"}`。くり返しの文や短い問いかけでも、文がまるごと無ければ `{"ko"}`。それより短い語句が落ちて中身が変わるなら `diff`。言い回し・意訳・まとめ方の違いは何も書かない
- 英語にだけあって韓国語に無い文は、いちばん近い組の `en` に入れ、`en_only` も書く
- `note` は作業者向けのメモ（画面に出ない）。**日本語で**短く

### 読む人向けの注（画面に出る。英語の欄に出すので英語で書く）

**`diff`（英語の欄の下に「※」で出る）** … 英語版が**中身を書き換えている所**を、1つ1文で英語で書く。
- 対象: 数・年・日付・人・場所・主語と目的語・打ち消し（逆の意味）・列挙の項目が変わる所と、例えや理由の中身が別のものになっている所
- 形: **In the original, … (the English edition has "…").** 原文の中身は自分で英語に訳して書く
  - 例 "In the original, the number of member nations is 53 (the English edition has "51")."
- 書かないもの: 言い回し・意訳の違い／英語圏向けに足した短い説明／「天一国5年」→「2005」のような年の数え方の書き換え・おおよその数の言い方／英語に無い文や語句で `{"ko"}` の AI 訳で補うもの
- 番号（E12・K3・組）や作業の言葉は入れない

**`en_only` と `en_only_ko`（英語版にしか無い文）** … 英語版にあって**原文の韓国語に無い文**を、その組の `en` にある文の番号で `en_only` に並べる。文の一部に説明が足されているだけなら入れない。`en_only_ko` には、その文（複数なら全部）を韓国語に訳して書く（「-습니다」体）

### 迷いやすい所（韓日のときに決めたこと）
- **韓国語の原文のほうが誤りらしい所**: `diff` は書かず、`note` に「原文の疑い: 〜」（韓日の対応表の note にもう書いてあれば、それに合わせる）
- **英語版の字の誤り**（綴りの誤り・抜けた字）: `diff` にせず、`note` に「英語の字: 〜」
- **英語の1文が2つに切れている所**（略語のピリオドなど）: 2つとも同じ組に入れる

## 確かめる
書いたら、リポジトリの根（`E:\mimune-no-uraniwa\mimune-no-uraniwa`）で

    python -I -X utf8 _tools/heiwakyou_taiyaku/check_align.py HHNN --lang en

を回し、「誤り」が無くなって `OK` が出るまで直す。「知らせ」は誤りではないが、目を通して、おかしければ直す。

## 気をつけること
- 渡された講演だけを書く。ほかのファイル（材料・スクリプト・ほかの講演・韓日の対応表）は触らない
- 韓国語・英語の本文を直さない。対応を付けるだけ
- 推測で埋めない。韓国語を読んで、英語のどの文が同じことを言っているかを確かめて組にする
- 長い講演も、最初から最後まで全部読んで組にする。途中から機械的に割り振らない
